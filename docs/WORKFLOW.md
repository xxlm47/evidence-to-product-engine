# Operating Workflow

## Recommended flow

1. Create a new project:
   ```bash
   ./scripts/new-project.sh
   ```
2. Work in `work/<slug>/`
3. Start with the research brief in `research/RESEARCH-BRIEF.md`
4. Document demand and competitor evidence
5. Decide whether the opportunity is strong enough to proceed
6. Fill the outline and draft only after evidence is documented
7. Fact-check, edit, package, and prepare launch assets
8. Human approval is required before publication

## Project lifecycle

`INTAKE -> RESEARCH -> OPPORTUNITY -> OUTLINE -> DRAFT -> FACT_CHECK -> EDIT -> PACKAGE -> LAUNCH -> MEASURE`

## Project layout

```text
work/<slug>/
  README.md
  project.json
  research/
  opportunity/
  outline/
  manuscript/
  packaging/
  launch/
  metrics/
```

## Important rules

- Start with a real problem, not a vague idea
- Research before writing the manuscript
- Use evidence to justify decisions and the go/no-go gate
- Keep all source information in the project files
- Do not claim income or demand without evidence
- Human approval remains mandatory before publishing

## Productization path

- Phase 1: free open workflow
- Phase 2: polished browser app and templates
- Phase 3: automation and provider adapters
- Phase 4: analytics and management tools
- Phase 5: paid hosted convenience features only after free value is proven

Do not introduce paid infrastructure merely to look like a SaaS. Validate usefulness first.
